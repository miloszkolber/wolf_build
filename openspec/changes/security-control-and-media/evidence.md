The reviewed Wolf input is upstream commit `db709cfd3f0f49dfd7d00495940119309692b535`. The upstream [PR 558](https://github.com/games-on-whales/wolf/pull/558) diff applies cleanly to that source. The local follow-up adds binary GCM tag sizing and pairing exception boundaries; it does not merge the beta branch.

In the development container, the complete PR and local follow-up applied after exact source-hash verification. Focused C++ regressions compiled upstream control, crypto and pairing protocol code against OpenSSL. They passed valid control packets, tags both with and without NUL bytes, altered tags and ciphertext, wrong keys, short tags, invalid IV lengths, a complete valid four-phase protocol exchange and malformed phase-2/3 challenges. The tests substitute minimal definitions for unrelated types. They do not run the HTTP or ENet servers or prove final-image behavior.

The development container also compiled upstream audio packetization and buffer encryption against extracted GStreamer and OpenSSL libraries. A valid audio buffer round-tripped through the generated encrypted RTP payload. A nonnumeric IV produced empty packet lists on repeated attempts without consuming a sequence number. The harness substitutes FEC and logging and does not test FEC or a live GStreamer pipeline.

## Certificate and packet-length follow-up

The subsequent stable adaptation uses [PR 566](https://github.com/games-on-whales/wolf/pull/566) and [PR 570](https://github.com/games-on-whales/wolf/pull/570) without enabling the insecure issuer override. Its new source check includes the original `x509.cpp` hash. The earlier local tag-size and binary-tag fixes overlap PR 570. The patch and regression sources participate in the existing runtime identity.

In the development container, all three patches applied to the exact stable source. The focused verifier and control harnesses compiled with AddressSanitizer and UndefinedBehaviorSanitizer and passed. The verifier tested two paired-certificate match matrices, an unrelated self-signed certificate, an unknown-issuer forgery with and without the upstream override environment variable, a signed partial chain, a bad issuer signature and an expired signed certificate. The control harness tested a valid minimum-length encrypted payload, truncated received buffers, all declared lengths below the minimum, an oversized declaration and exact-size received copies with binary tags. Expected OpenSSL errors were printed for deliberate invalid crypto operations.

The certificate matrix calls the real OpenSSL-backed verifier, not the paired-client lookup or HTTPS server. The packet tests call the real bounds helper and decryptor, not the ENet event loop. The new source-level header guard was inspected but not endpoint-tested. No actual embedded or Moonlight client, final image, Intel device or session was tested for this follow-up. Unknown-issuer clients previously accepted by the workaround may be rejected. Further authenticated-input bounds and nonce reuse remain outside this repair.

An independent source audit confirmed the production paired-client lookup invokes the verifier and that the ENet header and length guards precede the affected reads and decryption. It found no supported acceptance-blocking defect. It did not execute the sanitizer harness or actual HTTPS/ENet traffic.

The development container ran `python3 -m unittest discover -s tests`: 86 tests passed, including an expected rejected patch. `bun scripts/check-docs.mjs` checked 40 Markdown files without failures. `OPENSPEC_TELEMETRY=0 bun x --bun @fission-ai/openspec@1.14.1 validate --all --strict` passed four specifications and this change. These checks do not establish image or client acceptance.
