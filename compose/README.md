# Gate-only example
This example consumes the gate image from `llama_build`. It does not build or provision a Wolf runtime. The runtime container must already exist, share host networking, own its required devices/state and expose the configured TCP ports with a working Docker health check. Copy `gate.env.example` to `gate.env`, select an accepted universal gate version/digest and set the actual socket group/path. `GATE_CONTAINER_NAME` must match the deployed gate name. Validate without starting containers:
```sh
docker compose --env-file compose/gate.env -f compose/gate.compose.yaml config --quiet
``` The example has no gate configuration-file mount, `--config` argument, build context or GPU devices. The local environment file is ignored by git. It is the intended settings owner rather than an opaque JSON replacement. Runtime state/TOML and pairing certificates are preserved in the runtime's own deployment. Deploy/reconcile only with separate authorization while sessions are idle. Gate restart can stop the managed runtime. Gate `--health` proves binary execution, not socket access or streaming readiness. Intel Wolf runtime implementation and full Moonlight acceptance remain pending.
